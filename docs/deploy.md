# Деплой Salary: пошаговая инструкция

Как выложить Salary в интернет: база данных в **Turso**, сайт на **Vercel**. Всё бесплатно в рамках начальных тарифов. Займёт около 30 минут.

> **Что уже сделано в коде.** При каждой публикации Vercel сам проверяет настройки (`scripts/check-env.mjs`) и обновляет структуру базы (`scripts/migrate.mjs`). Если чего-то не хватает, сборка остановится с понятным сообщением на русском. Адрес `/api/health` показывает, что сайт работает и база отвечает.

---

## Шаг 1. База данных Turso

*Turso — это «склад в интернете», где будут храниться все пользователи и их операции.*

1. Зарегистрируйтесь на [turso.tech](https://turso.tech) (можно через GitHub).
2. Установите программу Turso на компьютер:
   - macOS: `brew install tursodatabase/tap/turso`
   - Linux / Windows (WSL): `curl -sSfL https://get.tur.so/install.sh | bash`
3. Войдите в аккаунт:

   ```bash
   turso auth login
   ```

4. Создайте базу. Регион выберите ближе к пользователям, например `fra` — Франкфурт:

   ```bash
   turso db create salary --location fra
   ```

5. Получите **адрес базы** и сохраните его, он понадобится на шаге 3:

   ```bash
   turso db show salary --url
   ```

   Он выглядит так: `libsql://salary-ваш-логин.aws-eu-central-1.turso.io`.

6. Создайте **токен доступа** и тоже сохраните его. Это пароль от базы, никому его не показывайте:

   ```bash
   turso db tokens create salary
   ```

Создавать таблицы вручную не нужно: Vercel сделает это сам при первой публикации.

## Шаг 2. Секретный ключ

*Ключ, которым сайт подписывает «пропуска» вошедших пользователей.*

Выполните в терминале и сохраните результат (строка примерно из 44 символов):

```bash
openssl rand -base64 32
```

Нет `openssl`? Подойдёт любой генератор паролей: строка из 40+ случайных букв и цифр.

## Шаг 3. Сайт на Vercel

1. Зарегистрируйтесь на [vercel.com](https://vercel.com) **через GitHub**.
2. Нажмите **Add New → Project** и выберите репозиторий `salary`. Если его нет в списке, нажмите **Adjust GitHub App Permissions** и дайте Vercel доступ к репозиторию.
3. Vercel сам определит Next.js. Настройки сборки менять не нужно.
4. Откройте **Environment Variables** и добавьте три переменные (Environments: **Production** и **Preview**):

   | Имя | Значение |
   |-----|----------|
   | `TURSO_DATABASE_URL` | адрес из шага 1.5 (`libsql://…`) |
   | `TURSO_AUTH_TOKEN` | токен из шага 1.6 |
   | `BETTER_AUTH_SECRET` | ключ из шага 2 |

   Нажмите **Deploy**. Адрес сайта (`https://salary-xxx.vercel.app`) подставится автоматически. Переменная `BETTER_AUTH_URL` нужна, только если вы подключите **свой домен** (Settings → Domains): тогда задайте её для Production со значением `https://ваш-домен.ru` и сделайте **Deployments → … → Redeploy**.

5. Подождите 2–3 минуты, пока идёт сборка. В журнале сборки должны появиться строки:

   ```
   ⚠ BETTER_AUTH_URL не задан — используется адрес проекта https://salary-xxx.vercel.app…
   ✓ Переменные окружения в порядке
   ✓ Миграции применены (salary-….turso.io)
   ```

> **Preview-версии.** Vercel публикует каждую ветку и pull request по отдельному адресу. Вход по email и паролю работает и там: адрес подставляется автоматически. **Preview и Production пользуются одной базой.** Если нужна отдельная база для экспериментов, создайте вторую (`turso db create salary-preview`) и укажите её переменные только для Preview.

## Шаг 4. Вход через Google (по желанию)

Без этого шага кнопка «Войти через Google» просто не показывается.

1. Откройте [console.cloud.google.com](https://console.cloud.google.com) и создайте проект **Salary**.
2. Откройте **APIs & Services → OAuth consent screen**: тип **External**, название «Salary», ваш email. Сохраните.
3. Откройте **APIs & Services → Credentials → Create credentials → OAuth client ID**:
   - Application type: **Web application**
   - Authorized redirect URIs:
     - `https://salary-xxx.vercel.app/api/auth/callback/google` — ваш адрес из шага 3
     - `http://localhost:3000/api/auth/callback/google` — для работы на своём компьютере
4. Скопируйте **Client ID** и **Client secret** в Vercel как `GOOGLE_CLIENT_ID` и `GOOGLE_CLIENT_SECRET` (Production) и сделайте **Redeploy**.

> На preview-адресах вход через Google работать не будет: Google пускает только на заранее указанные адреса. Для проверки используйте email и пароль.

## Шаг 5. Проверка после деплоя (smoke-тест)

Откройте сайт и пройдите короткий список:

- [ ] `https://ваш-адрес/api/health` показывает `{"status":"ok"}`
- [ ] Главная открывается, есть кнопка «Начать бесплатно»
- [ ] Регистрация работает и открывает дашборд с приглашением добавить операцию
- [ ] Кнопка «+» добавляет доход и расход, на дашборде появляются цифры и графики
- [ ] В разделе «Категории» видны суммы, в «Операциях» работает поиск
- [ ] Бюджет создаётся, статус меняется при тратах
- [ ] «Настройки → Экспорт → Скачать CSV» скачивает файл, и он открывается в Excel
- [ ] Выход и повторный вход работают
- [ ] (если включали) «Войти через Google» работает
- [ ] На телефоне всё помещается по ширине, работает нижняя панель

Если `/api/health` показывает `{"status":"error"}`, значит, сайт не может достучаться до базы. Проверьте `TURSO_DATABASE_URL` и `TURSO_AUTH_TOKEN` в Vercel. Если токен отозван, создайте новый (шаг 1.6).

## Шаг 6. Автоматические проверки на GitHub

В репозитории есть `.github/workflows/ci.yml`. При каждом push GitHub Actions запускает:

1. проверку кода, типов и модульные тесты;
2. сквозные тесты Playwright: регистрацию, операции, бюджеты, экспорт, безопасность, доступность.

Результаты — во вкладке **Actions** репозитория. Красный крестик значит, что что-то сломалось, лучше разобраться до деплоя. Vercel публикует сайт независимо от этих проверок.

## Работа на своём компьютере

```bash
pnpm install
cp .env.example .env.local       # заполнить BETTER_AUTH_SECRET
pnpm db:migrate
pnpm dev                          # http://localhost:3000
```

Для локальной разработки база — файл `local.db`, Turso не нужен. Проверить настройки: `pnpm check-env`.

## Что где лежит

| Что | Где |
|-----|-----|
| Проверка переменных окружения | `scripts/check-env.mjs` (`pnpm check-env`) |
| Миграции при сборке на Vercel | `scripts/migrate.mjs`, скрипт `vercel-build` в `package.json` |
| Проверка «сайт жив» | `GET /api/health` → `{"status":"ok"}` или `503` |
| Заголовки безопасности | `next.config.ts` |
| CI | `.github/workflows/ci.yml` |
