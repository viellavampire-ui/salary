# Task Guide — тот же план, но простыми словами

> **Где мы сейчас:** шаги 1–8 готовы — сайт запускается, можно зарегистрироваться, войти и выйти, новые пользователи сразу получают набор категорий, а по разделам можно ходить через меню (слева на компьютере, внизу на телефоне). Есть и «помощники» для денег и дат, проверенные сотней автоматических тестов. Раздел «Категории» уже работает: можно создавать свои категории, менять иконку и цвет, убирать в архив и возвращать. Дальше — шаг 9 (добавление доходов и расходов).

Этот документ повторяет `task.md` шаг за шагом, но объясняет каждое действие так, чтобы понял человек без опыта программирования. Номера шагов совпадают.

> **Мини-словарь**
> - **Приложение / сайт** — то, что мы строим: личный кошелёк-аналитик «Salary» в браузере.
> - **Next.js** — «конструктор», на котором собирается сайт: и то, что видит пользователь, и то, что работает «за кулисами».
> - **База данных (Turso)** — большая надёжная таблица в интернете, где хранятся все записи: пользователи, доходы, расходы.
> - **Авторизация** — вход по логину и паролю, чтобы каждый видел только свои деньги.
> - **Терминал** — окно, куда вводятся текстовые команды для компьютера.
> - **Git / GitHub** — «машина времени» для кода: сохраняет все версии и хранит копию в интернете.

---

## 1. Подготовка окружения
*Готовим компьютер к работе — как раскладываем инструменты перед ремонтом.*

- **1.1** Устанавливаем Node.js — это «двигатель», без которого сайт не запустится на компьютере. pnpm — «грузчик», который скачивает готовые детали (библиотеки) для проекта.
- **1.2** Устанавливаем Git и заводим «папку в облаке» на GitHub, где будет храниться проект и вся его история изменений.
- **1.3** Устанавливаем программу Turso и регистрируемся. Через неё мы будем создавать и управлять базой данных.
- **1.4** Ставим редактор кода VS Code (как Word, только для программ) и дополнения, которые подсвечивают ошибки и сами выравнивают текст кода.

## 2. Создание проекта Next.js
*Закладываем фундамент дома.*

- **2.1** Одной командой создаём пустой «скелет» сайта — готовую заготовку с базовыми настройками.
- **2.2** Включаем «строгий режим»: компьютер будет заранее предупреждать о многих ошибках. Настраиваем автоматическое форматирование, чтобы код всегда выглядел аккуратно.
- **2.3** Раскладываем проект по папкам: отдельно внешний вид, отдельно база данных, отдельно вспомогательные функции — как в шкафу с подписанными полками.
- **2.4** Делаем первое «сохранение» проекта и отправляем копию на GitHub.

## 3. Дизайн-система
*Выбираем краски, шрифты и «кирпичики» интерфейса, чтобы всё выглядело единообразно.*

- **3.1** Подключаем shadcn/ui — набор готовых красивых элементов (кнопки, поля, окошки), которые мы будем использовать как конструктор Lego.
- **3.2** Записываем в один файл все цвета из `design.md`: индиго для кнопок, зелёный для доходов, красный для расходов и 8 цветов для категорий. Отдельно — для светлой и для тёмной темы.
- **3.3** Задаём, насколько скруглены углы (8–12 пикселей) и какие отступы между элементами.
- **3.4** Подключаем шрифт Inter с поддержкой русских букв. Настраиваем цифры так, чтобы все они были одинаковой ширины — суммы в столбик будут ровными.
- **3.5** Скачиваем нужные «кирпичики»: кнопки, поля ввода, выпадающие списки, всплывающие окна, таблицы, календарь, уведомления и т.д.
- **3.6** Добавляем переключатель темы: светлая, тёмная или «как в системе телефона/компьютера».
- **3.7** Подключаем набор иконок и делаем «значок категории» — иконку в цветном кружочке (например, тележка 🛒 для «Продуктов»).
- **3.8** Если у человека в настройках включено «уменьшить движение», сайт отключает анимации.

## 4. База данных Turso + Drizzle
*Строим «склад», где будут храниться все записи о деньгах.*

- **4.1** Создаём базу данных в Turso и получаем два «ключа»: адрес базы и секретный пароль доступа.
- **4.2** Записываем эти ключи в специальный секретный файл на компьютере. Говорим Git никогда не отправлять этот файл в интернет, чтобы никто чужой не получил доступ.
- **4.3** Скачиваем Drizzle — «переводчик», который позволяет говорить с базой данных на понятном программе языке, а не писать сложные запросы вручную.
- **4.4** Соединяем проект с базой данных — как подключаем телефон к Wi-Fi.
- **4.5** Описываем, какие «таблицы» будут на складе:
  - **Категории** — название, доход это или расход, иконка, цвет.
  - **Операции** — сумма, дата, категория, комментарий.
  - **Бюджеты** — лимит трат на категорию в месяц.
  Суммы храним в копейках (целым числом), чтобы не было ошибок округления вроде 0,1 + 0,2 = 0,30000004.
- **4.6** Создаём короткие команды-ярлыки, чтобы одним словом обновлять структуру базы или посмотреть её содержимое в удобном окне.

## 5. Авторизация (Better Auth)
*Ставим «дверь с замком»: каждый пользователь заходит под своим логином и видит только свои деньги.*

- **5.1** Подключаем Better Auth — готовую систему входа. Говорим ей хранить пользователей в нашей базе Turso.
- **5.2** Добавляем каждому пользователю личные настройки: валюту (рубли, доллары…) и с какого числа у него начинается «финансовый месяц» (например, с дня зарплаты).
- **5.3** Система входа сама создаёт нужные таблицы (пользователи, сессии); мы добавляем их на склад.
- **5.4** Создаём «адрес», по которому сайт обрабатывает вход, выход и регистрацию.
- **5.5** Делаем «пульт» для страниц, чтобы кнопки «Войти» и «Выйти» могли общаться с системой входа.
- **5.6** Настраиваем вход через Google: регистрируем наше приложение у Google и получаем ключи. Теперь можно войти одной кнопкой.
- **5.7** Ставим «охранника» на вход: если человек не вошёл в аккаунт и пытается открыть свои финансы, его отправляют на страницу входа.
- **5.8** Делаем вспомогательную проверку «кто сейчас пользователь?», которую будем использовать на каждой странице.
- **5.9** Рисуем страницы «Вход» и «Регистрация»: поля email и пароль, кнопка Google, понятные сообщения об ошибках («Пароль слишком короткий»).
- **5.10** Когда человек регистрируется, ему автоматически создаётся набор стандартных категорий: Продукты, Жильё, Транспорт, Зарплата и т.д. — чтобы не начинать с пустого места.
- **5.11** Проверяем вручную: зарегистрировались → в базе появился пользователь и его категории → вышли → снова вошли.

## 6. Каркас приложения (layout)
*Строим «стены и коридоры» — меню и общую рамку, внутри которой будут все страницы.*

- **6.1** Делаем боковое меню слева на компьютере. На планшете оно сужается до иконок, на телефоне превращается в панель внизу экрана.
- **6.2** Рисуем пункты меню (Дашборд, Операции, Категории, Бюджеты, Аналитика, Настройки), большую кнопку «+» на телефоне и меню профиля с аватаром, темой и выходом.
- **6.3** Делаем переключатель месяца со стрелками ◀ Ноябрь 2026 ▶. Выбранный месяц записывается в адрес страницы — ссылку можно сохранить или отправить.
- **6.4** Создаём пустые страницы-заготовки для всех разделов, чтобы навигация уже работала.
- **6.5** Главная страница: если человек уже вошёл — сразу показываем ему дашборд, если нет — короткую страницу о приложении с кнопкой «Начать».

## 7. Утилиты
*Делаем маленькие «помощники», которые будут использоваться везде.*

- **7.1** Помощник для денег: превращает «1 234,56» в копейки и обратно, красиво показывает «1 234,56 ₽» и сокращает большие числа на графиках (45K, 1,2M).
- **7.2** Помощник для дат: понимает, где начало и конец месяца, квартала, года, и какой период был «прошлым» для сравнения.
- **7.3** Правила проверки данных: сумма должна быть больше нуля, название категории не пустое, дата адекватная и т.д.
- **7.4** Пишем автоматические проверки этих помощников — программа сама убеждается, что 100 рублей = 10 000 копеек и т.п.

## 8. Категории
*Раздел, где пользователь управляет «папками» для своих денег.*

- **8.1** Учим сайт доставать из базы список категорий пользователя и сколько в каждой потрачено за месяц.
- **8.2** Учим сайт создавать, переименовывать и архивировать категории. Удалять категорию, в которой уже есть операции, нельзя — только спрятать в архив, чтобы не потерять историю.
- **8.3** Делаем выбор иконки (около 40 вариантов) и выбор цвета (8 вариантов).
- **8.4** Рисуем страницу «Категории» с двумя вкладками — «Расходы» и «Доходы» — и плитками категорий. Нажал на плитку — открылась панель редактирования.
- **8.5** Продумываем, что показывать, пока данные загружаются, и что показывать, если категорий нет.

## 9. Операции (транзакции)
*Главная функция: записать «пришло» или «ушло».*

- **9.1** Учим сайт добавлять, менять, удалять и восстанавливать операции. При этом сайт проверяет, что категория действительно принадлежит этому пользователю.
- **9.2** Рисуем форму добавления: переключатель «Доход / Расход», большое поле для суммы, выбор категории иконками, дата (по умолчанию сегодня) и комментарий.
- **9.3** Форма открывается выдвижной панелью справа на компьютере и снизу на телефоне. Кнопка «+ Операция» доступна с любой страницы.
- **9.4** Учим сайт показывать список операций порциями по 25 штук, чтобы страница не тормозила.
- **9.5** Рисуем страницу «Операции»: сверху фильтры (период, тип, категория, поиск по комментарию), ниже таблица. На телефоне — список, сгруппированный по дням.
- **9.6** При удалении появляется сообщение «Операция удалена» с кнопкой «Отменить» на 5 секунд — на случай, если нажали случайно.
- **9.7** После любого изменения дашборд и другие страницы сразу показывают актуальные цифры.

## 10. Дашборд и графики
*Главный экран — «приборная панель» финансов.*

- **10.1** Подключаем Recharts — библиотеку для рисования графиков.
- **10.2** Учим сайт считать: сколько пришло и ушло за месяц, остаток, процент сбережений, расходы по каждой категории, доходы по источникам, динамику за 12 месяцев.
- **10.3** Делаем 4 карточки сверху: Доходы, Расходы, Баланс, Норма сбережений. Под каждой суммой — стрелочка ▲/▼ и на сколько процентов изменилось по сравнению с прошлым месяцем.
- **10.4** Рисуем график «Расходы по категориям» — горизонтальные полоски от самой большой к самой маленькой. Если категорий больше 8, мелкие объединяются в «Прочее».
- **10.5** Рисуем график «Доходы и расходы за год»: по каждому месяцу два столбика (зелёный и красный) и линия остатка.
- **10.6** Настраиваем подсказки при наведении мыши, подписи, сетку и цвета так, чтобы графики хорошо смотрелись и в светлой, и в тёмной теме.
- **10.7** Под каждым графиком кнопка «Показать как таблицу» — для тех, кому так удобнее, и для людей, использующих программы чтения экрана.
- **10.8** Собираем всё на одной странице по макету из `design.md`. Пока данные грузятся, показываем серые «заглушки» нужной формы.
- **10.9** Для нового пользователя без операций показываем дружелюбный экран «Добавьте первую операцию» с кнопкой.

## 11. Бюджеты
*Лимиты, чтобы не тратить больше запланированного.*

- **11.1** Учим сайт сохранять лимит для категории (например, «Кафе — 10 000 ₽ в месяц») и считать, сколько уже потрачено.
- **11.2** Рисуем страницу «Бюджеты» с полосками прогресса: синяя — всё хорошо, жёлтая — потрачено 80% и больше, красная — лимит превышен.
- **11.3** На дашборд добавляем блок «Бюджеты под угрозой», чтобы сразу видеть проблемные категории.

## 12. Аналитика
*Подробный разбор за любой период.*

- **12.1** Делаем выбор периода: месяц, квартал, год или свои даты «с … по …».
- **12.2** Учим сайт находить 5 самых крупных трат и сравнивать период с предыдущим.
- **12.3** Рисуем графики: как менялись расходы со временем, на что уходят деньги, откуда приходят, топ-5 трат.

## 13. Настройки
*Личные предпочтения пользователя.*

- **13.1** Форма настроек: валюта, первый день финансового месяца, тема оформления.
- **13.2** Кнопка «Скачать CSV» — выгружает все операции в файл, который открывается в Excel.
- **13.3** Возможность сменить пароль.
- **13.4** Кнопка «Удалить аккаунт». Чтобы не нажать случайно, нужно вписать слово «УДАЛИТЬ». Удаляются все данные пользователя.

## 14. Качество и безопасность
*Проверяем, что всё работает и что чужие данные надёжно защищены.*

- **14.1** Автоматическая проверка: создаём двух пользователей и убеждаемся, что второй никак не может увидеть или изменить деньги первого.
- **14.2** «Робот-тестировщик» сам проходит весь путь пользователя: регистрируется, добавляет доход и расход, смотрит дашборд, создаёт бюджет, скачивает файл.
- **14.3** Включаем защитные настройки сайта против распространённых атак.
- **14.4** Проверяем, что сайтом удобно пользоваться людям с ограниченными возможностями: достаточно контрастный текст, можно управлять только клавиатурой.
- **14.5** Проверяем сайт на экранах разных размеров (телефон, планшет, ноутбук, большой монитор) в светлой и тёмной теме.
- **14.6** Прогоняем сайт через Lighthouse (бесплатный «тестер» от Google) — он ставит оценки скорости и удобства. Цель — 90+ баллов.

## 15. Деплой (публикация)
*Выкладываем сайт в интернет, чтобы им могли пользоваться все.*

- **15.1** Регистрируемся в Vercel (хостинг для сайтов на Next.js) и связываем его с нашим проектом на GitHub. Теперь каждое сохранение автоматически обновляет сайт.
- **15.2** Вписываем в Vercel те же секретные ключи (база, вход, Google), что лежали в секретном файле на компьютере.
- **15.3** Создаём структуру таблиц в «боевой» базе данных.
- **15.4** Сообщаем Google настоящий адрес сайта, чтобы кнопка «Войти через Google» работала и там.
- **15.5** Открываем сайт по настоящему адресу и проверяем основные действия руками: регистрация, добавление операций, графики.
- **15.6** Проходимся по итоговому чек-листу из `SPEC.md` и отмечаем галочками всё, что готово. Готово — MVP запущен! 🎉
